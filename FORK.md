# JJstack — fork notes

JJstack is a fork of [gstack](https://github.com/garrytan/gstack), Garry Tan's
AI engineering workflow. We track upstream so we keep getting his improvements,
and we add our own delivery routes on top.

## Why we keep the gstack identity

We deliberately do **not** rebrand the internals. The skill prefix, `README.md`,
and `CLAUDE.md` all still say "gstack". Renaming them would conflict with every
upstream release and slowly make upstream merges impossible. Keeping the identity
keeps merges clean. Our additions live in new files and directories that upstream
never touches, so the conflict surface is tiny.

## Staying current with upstream

One-time, on your machine:

```bash
git remote add upstream https://github.com/garrytan/gstack.git
```

To pull the latest upstream changes onto a sync branch:

```bash
git fetch upstream
git checkout -b sync-upstream
git merge upstream/main
```

Conflict guidance:

- **Generated `SKILL.md` files** — never resolve by picking a side. Resolve the
  `.tmpl` templates (and `scripts/gen-skill-docs.ts`) instead, then run
  `bun run gen:skill-docs` and stage the regenerated output. See CLAUDE.md,
  "Merge conflicts on SKILL.md files".
- **`AGENTS.md` / `docs/skills.md`** — our route skills add rows here. Keep both
  upstream's new entries and our route-selection blocks.
- Run `bun test` before merging back. Every gate must be green.

Then open a PR from `sync-upstream` into your `main`.

## What this fork adds — the three-route stack

Upstream gstack assumes you are building a commercial product. This fork adds a
router and two more delivery routes. Pick the route once per project; the same
build → `/review` → `/qa` → `/ship` tail applies to all three.

| Route | For | Plan gate |
|-------|-----|-----------|
| **VC** | Commercial product | `/market-fit` |
| **DX** | Client / org digital transformation from a strategic insight | `/transform` |
| **Sandbox** | Personal, non-commercial invention | `/problem-solver` |

`/discovery` picks the route and writes a committed `.gstack-route` file at the
repo root so teammates inherit it.

The only files that differ from upstream (the entire merge-conflict surface):

- `discovery/`, `market-fit/`, `transform/`, `problem-solver/` — new skill dirs
  (each a `SKILL.md.tmpl` plus its generated `SKILL.md`).
- `AGENTS.md`, `docs/skills.md` — the four skills registered (required by tests).
- `gstack/llms.txt` — regenerated by `bun run gen:skill-docs`.
- `docs/idea-handoff-prompt.md` — the claude.ai → Claude Code briefing prompt.
- This file.

## Handoff from claude.ai chat to Claude Code

If you brainstorm ideas in regular claude.ai chat first, paste the prompt in
[`docs/idea-handoff-prompt.md`](docs/idea-handoff-prompt.md) into a claude.ai
Project's Custom Instructions. Every chat inside that Project then exposes a
one-trigger `/handoff` that produces a structured `briefing.md` the gstack
plan-gates can ingest in one read. See the doc for the full setup.

## Installing this fork for teammates

Optional, only when you distribute to the team. Same as gstack's install, but
clone this repo instead of upstream:

```bash
git clone https://github.com/jamiejefferson/JJstack.git ~/.claude/skills/gstack && cd ~/.claude/skills/gstack && ./setup
```

The clone target stays `~/.claude/skills/gstack` — the skill system expects that
path and the gstack identity. That is exactly why we don't rebrand.
